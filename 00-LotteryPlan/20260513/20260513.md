## 7. 風險與不確定點

### 7.1 PR #88 是否仍有價值

PR #88 是較早的 P70 operator evidence docs，已經 BEHIND main。由於 PR #90 已包含更完整的 Browser Visual QA evidence，PR #88 可能已被 supersede。

風險：

* 若直接 merge，可能增加重複報告。
* 若 close，需確認 PR #88 沒有唯一資訊。

### 7.2 P78 需要謹慎避免破壞 production same-origin

P78 的核心要求是：

* production 預設仍走 `/api/replay`
* local dev 才透過 `window.API_BASE='http://localhost:8002'`

風險：

* 若不小心 hardcode `localhost:8002`，會污染 production path。
* 若漏掉某些 `/api/` fetch，local dev 還是需要 fetch proxy。
* 若設定 API base 時處理 slash 不當，可能產生 `//api/replay` 或重複 slash。

### 7.3 Browser QA 路徑仍需再驗證

P76 是用 fetch proxy workaround 捕捉 evidence。P78 之後應該要再做一次 browser smoke，確認不再需要 Playwright fetch monkey patch。
