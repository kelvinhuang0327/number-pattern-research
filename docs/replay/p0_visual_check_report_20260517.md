## 7. CEO 視角 Product Gap（5 bullets）

1. **策略宇宙覆蓋率嚴重不足**：UI 只顯示 18/506 策略（3.6%）。488 個策略（包含大量 RETIRED/REJECTED 歷史策略）不在 DB registry 中，等同於在產品中「消失」。這是滿足「所有策略 × 所有歷史期數」目標的最大障礙。

2. **Dev 啟動文件缺口**：production same-origin 設計正確，但開發者在 dev 環境需要知道啟動時加 `window.API_BASE` 或使用 injection wrapper。沒有文件說明這一點，導致連 CTO 團隊都以為頁面壞了（P5/P6 系列的「資料讀取失敗」就是這個問題）。

3. **Coverage 全部「限制性」**：三種彩種的 replay coverage 都顯示 ⚠️限制性。每個 run 只有 100 期數據。用戶期望的「所有歷史期數」目前還差很遠。

4. **P1 lifecycle 術語與 DB 不一致**：P1 governance 花費大量工時定義 7 個 lifecycle states，但 DB 實際使用的是 ONLINE/REJECTED/OBSERVATION/RETIRED。這 7 個治理概念大部分沒有落地到 DB，意味著 P1 工作成果主要存在於 governance artifacts，不在實際系統中。

5. **407 DISPLAY_ONLY 無產品決策**：P3 分類了 407 個「只有展示，無歷史資料」的策略，但沒有決定它們在 UI 中怎麼呈現。目前的選擇是：(a) 加入 registry 顯示「無歷史資料」標籤；(b) 完全排除；(c) 說明為何不呈現。沒有決策就沒有實作。
